# Сервис форм

MVP для карьерной платформы: менеджер без разработчика собирает форму отклика, публикует её по ссылке и видит ответы вместе с анонимной воронкой заполнения.

## Запуск

Требуется Node.js 20 или новее.

```bash
npm install
npm start
```

Откройте <http://localhost:3000>. `npm install` устанавливает зависимости и автоматически собирает фронтенд; отдельная команда сборки, миграции и `.env` не нужны.

- `PORT` — порт сервера; по умолчанию `3000`.
- `ADMIN_PASSWORD` — единый пароль менеджера; по умолчанию `admin`.

Данные создаются при первом запуске в `data/db.json`. Для проверки админки войдите с паролем `admin`, если переменная `ADMIN_PASSWORD` не задана.

## Решение и модель данных

Главная проблема MVP — потеря студентов на длинных или непонятных формах: черновик ответа автоматически сохраняется в браузере, прогресс показывает заполнение обязательных вопросов, а менеджер видит воронку «просмотр → начало → отправка» и последний вопрос в незавершённой сессии. Это помогает понять, где стоит упростить форму, вместо того чтобы добавлять много второстепенных функций.

Хранимые сущности:

- **Form** — ID, название, описание, статус, публичный slug, даты создания/обновления и упорядоченный список полей.
- **Field** — ID, тип, заголовок, описание, placeholder, обязательность и варианты для выбора.
- **Response** — ID формы, анонимный session ID, ответы, сопоставленные с ID полей, и время отправки.
- **Event** — ID формы и сессии, тип (`view`, `start`, `field_focus`, `field_complete`, `submit`), ID поля при необходимости и время.

Ответы формы и события не содержат имени, телефона или email сессии: пользовательские контактные данные появляются только если сам менеджер добавил соответствующие вопросы.

## Стек и устройство

- **Frontend:** React 18, TypeScript (`strict`), Vite, CSS Modules и CSS-переменные, React Router, Zustand с persist, Radix UI, `@dnd-kit`, Zod для граничной серверной валидации.
- **Backend:** Node.js, Express 5, REST/JSON API; тот же Express-процесс раздаёт собранный SPA и обрабатывает `/api/*`.
- **Хранилище:** JSON-файл без внешней БД и нативных модулей. Записи выполняются последовательно, во временный файл с последующим атомарным `rename`. Формат удобен для локального MVP и переносимого запуска из клона.

Доступ к файлу изолирован в `server/storage.js`. Для перехода на PostgreSQL или другую БД достаточно сохранить операции чтения/обновления этого слоя, заменив файловый адаптер на реализацию с транзакциями; API и UI при этом остаются прежними. Для нескольких экземпляров приложения понадобится общее БД-хранилище вместо локального JSON.

## Не вошло в MVP

Регистрация, роли пользователей, загрузка файлов, условные и многостраничные поля, уведомления, локализация, интеграции и расширенная аналитика сознательно отложены. Следующими шагами были бы управление доступом менеджеров, улучшение метрик на основе согласованного определения «отвала», retention данных и полноценные серверные тесты.

## AI-инструменты

При создании использовался AI-ассистент на базе Copilot SDK в VS Code: для разработки каркаса и интерфейса, проверки интеграции API и локальной отладки. Поведение проверено сборкой, API-сценарием и проходом ключевого сценария в браузере.
